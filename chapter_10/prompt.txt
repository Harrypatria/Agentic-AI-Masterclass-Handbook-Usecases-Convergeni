SECTION 2 — PROBLEM STATEMENT
────────────────────────────────────────────────────────────────────────────────
BUSINESS / CLINICAL PROBLEM:
  Early detection of Type-2 diabetes risk is critical. Current workflows rely on
  reactive lab results. We need a proactive system that:
  1. Predicts diabetes probability from routine clinical features
  2. Deterministically flags out-of-range values
  3. Generates plain-language, structured clinical explanations via LLM
  4. Surfaces high-risk cases as alerts and actionable tasks

TARGET USERS:
  - Primary care physicians / clinic nurses
  - Population health / care management teams
  - Digital health product managers building clinical decision support

SUCCESS METRICS:
  - Model AUC-ROC ≥ 0.80 on holdout set (target ≥ 0.85 preferred)
  - Deterministic abnormal feature flags before any LLM call
  - Structured LLM output (risk_level, key_factors, recommendation, disclaimer)
  - Risk threshold alert at ≥ 0.70 probability
  - Full ITDO loop: Insight → Trigger (alert) → Decision → Operation (task)

SECTION 3 — DATASET & FEATURE SPECIFICATION
────────────────────────────────────────────────────────────────────────────────
PRIMARY DATASET: Pima Indians Diabetes Dataset (diabetes.csv)
  Source: UCI / Kaggle (exactly as used in chapter_10/dataset/diabetes.csv)
  Rows: 768 patients | Target: Outcome (0 = no diabetes, 1 = diabetes)

FEATURE LIST (exact order must be preserved):
  Pregnancies, Glucose, BloodPressure, SkinThickness, Insulin,
  BMI, DiabetesPedigreeFunction, Age

KNOWN DATA QUALITY ISSUE (must handle):
  Columns Glucose, BloodPressure, SkinThickness, Insulin, BMI contain
  biologically impossible zeros → treat as missing (replace 0 with NaN)
  before any imputation.

CLASS IMBALANCE: ~35% positive class → use stratify + class_weight if needed.

NORMAL RANGES (for deterministic flagging — hard-coded):
  Glucose: (70, 99)
  BloodPressure: (60, 80)
  BMI: (18.5, 24.9)
  Age: (0, 120)
  (other features: no hard clinical range for flagging)

SECTION 4 — DATA PIPELINE SPECIFICATION (CRISP-DM aligned with Chapter 10)
────────────────────────────────────────────────────────────────────────────────
PHASE 1 — DATA INGESTION & AUDIT (backend/data_pipeline.py)
  1. Load dataset/diabetes.csv
  2. Print shape, head, Outcome value_counts
  3. Explicitly count zeros in [Glucose, BloodPressure, SkinThickness, Insulin, BMI]
  4. Replace those zeros with np.nan
  5. Assert no other unexpected nulls after replacement

PHASE 2 — EXPLORATORY DATA ANALYSIS (notebooks/01_eda.ipynb)
  1. Outcome distribution (countplot + pie)
  2. Correlation heatmap (all features)
  3. Boxplots: Glucose, BMI, Age, BloodPressure by Outcome
  4. Histogram of Age / BMI stratified by Outcome
  5. Export all plots to /reports/eda/ as PNG (300 DPI)

PHASE 3 — PREPROCESSING (backend/preprocessing.py)
  Must use sklearn.pipeline.Pipeline:
  - SimpleImputer(strategy="median")
  - StandardScaler()
  - Train/test split: 80/20, stratify=y, random_state=42
  - Keep feature order exactly as FEATURE_NAMES list

PHASE 4 — MODEL TRAINING (backend/train.py)
  Train TWO candidate models inside identical pipeline shapes:
    Model A: RandomForestClassifier(n_estimators=200, max_depth=5, random_state=42)
    Model B: LogisticRegression(max_iter=1000)

  Evaluate on holdout: Accuracy, AUC-ROC, Confusion Matrix, Classification Report
  5-fold Stratified CV on full data for RandomForest
  Optional GridSearchCV on RandomForest:
    n_estimators: [100, 200, 300]
    max_depth: [3, 5, 7]
  Select best model (prefer RandomForest if AUC competitive)

PHASE 5 — MODEL EVALUATION (notebooks/02_evaluation.ipynb)
  1. Confusion matrix (normalized)
  2. ROC curve with AUC
  3. Precision-Recall curve
  4. Feature importance (RandomForest)
  5. Export metrics + plots to /reports/model_report.md

PHASE 6 — SERIALISATION
  pickle.dump(best_pipeline, open("saved_models/diabetes_model.sav", "wb"))
  Also save feature_names.json and metrics.json
  Provide helper:
    def predict_diabetes_proba(patient_data: list) -> float

PHASE 7 — DETERMINISTIC FLAGGING + AGENTIC LAYER (core of Chapter 10)
  NORMAL_RANGES dict (as specified above)
  def flag_abnormal_features(patient_data: list, feature_names: list) -> list
  Then feed ONLY the flags + probability into structured LLM prompt.

  Use Pydantic model:
  class ClinicalExplanation(BaseModel):
      risk_level: str          # "low" | "moderate" | "high"
      key_factors: list[str]
      recommendation: str
      disclaimer: str

  System prompt must enforce:
  - You are a clinical communication assistant, NOT a diagnosing physician
  - Reason ONLY from the provided flags
  - Never invent factors
  - Always include strong disclaimer

  Final callable:
  def run_health_copilot(patient_data: list) -> dict:
      probability = predict_diabetes_proba(patient_data)
      flags = flag_abnormal_features(...)
      explanation = explain_diagnosis(probability, flags)  # structured
      return {"probability": probability, "explanation": explanation.model_dump()}

SECTION 5 — BACKEND API SPECIFICATION (FastAPI)
────────────────────────────────────────────────────────────────────────────────
FILE: backend/main.py

ROUTES:
  POST /predict
    Body: list[float] of length 8 (or Pydantic PatientFeatures)
    Returns:
    {
      "probability": float,
      "risk_level": "low"|"moderate"|"high",
      "flags": list[str],
      "key_factors": list[str],
      "recommendation": str,
      "disclaimer": str,
      "prediction_id": uuid
    }

  POST /batch-predict
    Body: list of patient feature lists (max 200)
    Returns: list of prediction responses

  GET /model-metrics
    Returns: {auc_roc, accuracy, trained_at, model_version}

  GET /health
    Returns: {status: "ok", model_loaded: bool, version: str}

MIDDLEWARE:
  - CORS for VITE_APP_URL
  - Rate limiting (slowapi)
  - structlog JSON logging
  - Structured HTTPException

LLM Integration:
  Prefer Gemini (Google AI Studio native) or OpenAI.
  Use structured output / response_format / function calling.
  Never send raw feature vector to LLM — only probability + flags.
